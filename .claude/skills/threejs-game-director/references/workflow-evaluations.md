# Workflow Evaluations

For maintainers changing the pack, test actions and artifacts rather than instruction length, skill-name mentions, or report keywords. Mocked helper tests prove contracts; they do not establish that a game looks or plays better.

## Scenario Set

| Brief | Expected observable behavior |
| --- | --- |
| Small arcade game, desktop and touch, no premium request | A working loop with real input and retry; all production specialists loaded for the full game, relevant references at phase entry; no forced large art pipeline or unrelated content. |
| Premium animated encounter | Scoped asset plan, authored or user-supplied assets integrated at gameplay scale, imported models checked against the intake checklist, motion evidence and complete declared captures. |
| Narrow HUD spacing fix in an existing premium game | Preserve gameplay and art; load UI and affected QA guidance; targeted layout/build checks instead of new heroes or a full release audit. |
| Explicitly procedural premium racer | Authored forms, readable camera, measured graphics, genre-interpreted scorecard. |
| User changes hero requirements mid-build | Record the correction, update the affected work, continue independent work, and preserve completed assets instead of rebuilding them. |

## Reproducible Comparison

1. Save the baseline pack revision and candidate diff. Run both in fresh, isolated game directories with the same prompt, seed, installed dependencies, browser/GPU, and model/reasoning settings. Use the same scripted correction for recovery cases.
2. Collect tool actions, completed gameplay behaviors, integrated asset paths, captures, motion samples, renderer/physics counts, build/test results, and elapsed time. Count unnecessary stops and repeated verification separately from necessary recovery.
3. Compare playable results at the same game state and camera scale. Score with the actual ten-category rubric, interpreted through the genre. Inspect motion unpaused. Record quality regressions even if the candidate is faster or uses fewer tokens.
4. Report what was exercised and what remains untested. A routing rehearsal is not an end-to-end game build. Do not claim visual improvement until comparable rendered games support it.

Start with the offline helper tests and a generated-scaffold build/browser pass. Test both hosts when available rather than inferring Claude Code behavior from a Codex run. Keep evaluation artifacts outside the installed skills and retain only reproducible tests and concise findings in the repository.
